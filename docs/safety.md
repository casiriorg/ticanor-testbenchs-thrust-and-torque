# Safety design

A propeller on a test bench is dangerous. The software is built so that no single failure, of the PC, the cable,
the application or the operator's attention, leaves a motor running. It does not replace physical protection:
see "Physical measures" at the end.

## Layers

| Layer | Where | What it does |
|---|---|---|
| Physical | bench | Cage, battery disconnect within reach, bench clamped down |
| ESC | AMPX 40A | Stops by itself when the signal is lost for more than 0.3 s (per its manual) |
| Firmware | Nano | Arming, watchdog, ceiling, rise limit, latched emergency stop |
| Core | PC (Rust) | Arming preconditions, limits, dead-man, automatic cut-offs |
| Interface | PC (window) | Always-reachable stop, explicit arming, confirmations |

Each layer works without the ones above it.

## Firmware rules (`firmware/ThrustBench/src/actuators/ThrottleController.cpp`)

- Boots **disarmed**, with the minimum pulse (or no signal, configurable). Opening the serial port resets the board,
  so reconnecting always returns to this state.
- Throttle is only accepted while **armed**. Arming needs a magic value and is refused in any other state.
- **Watchdog:** armed and no valid frame from the PC for `WatchdogMs` (300 ms) sets throttle to zero and enters
  *failsafe*, which only Disarm leaves.
- **Ceiling:** throttle is clamped to `ThrottleMax` (60 % by default).
- **Rise limit:** `SlewPerSec`; reductions are never delayed.
- **Emergency stop:** immediate zero, latched until ClearEStop. Disarm does not clear it.
- Output and safety settings, and EEPROM writes, are refused while armed.
- The pulse is generated by Timer1 hardware, so its width cannot be disturbed by the rest of the program.

## Core rules (`app/crates/tb-core/src/safety.rs`, `services/bench.rs`)

- **Arming preconditions:** connected, a commanding throttle mode selected, device reports disarmed, operator
  confirmation for this arming.
- **Limits:** its own ceiling and rise limit (Settings), applied before the firmware's. The lower one wins.
- **Dead-man:** the window reports every 300 ms. If it stops for 1.5 s while armed (frozen, crashed, closed),
  the core disarms. Minimising the window can also trigger it; that is intended.
- **Measurement limits:** optional maximum thrust and torque; exceeding one cuts the throttle and disarms.
- **Link loss:** detected after 1.5 s without status. The session ends, the application shows a critical alarm
  and reconnects automatically, always disarmed. The motor has already been stopped by the firmware watchdog.
- **Emergency stop path:** uses a dedicated handle that bypasses the command queue and the main state lock, and is
  sent three times. It cannot fail and never waits.
- **Failed command:** if a throttle command is rejected or times out, the core cuts the throttle and disarms; if that
  fails too, it sends an emergency stop.
- **Shutdown:** closing the application sends an emergency stop and finishes the recording file.
- Tare and calibration are refused while armed.

## Interface rules (`app/src/components`)

- The **STOP** button is always visible, never disabled, never asks for confirmation, and stays above every dialog.
  The space bar does the same (Ctrl+Space while typing in a field).
- **Arming** always goes through a dialog whose confirmation box starts unticked. It shows the active limits and warns
  about an old tare or uncalibrated cells.
- The throttle slider returns to zero whenever the output is not armed.
- The actuator state is a large coloured label; red is used only for "armed" and the stop button.
- The throttle mode must be chosen after each first connection, before anything can be armed.
- Stopping a recording asks for confirmation and warns if the output is still armed. Disconnecting is refused while
  armed or recording. Closing the window while armed or recording asks first.
- Alarms stay on screen until dismissed and are written into the recording as events.

## What is tested

`cargo test -p tb-core` covers: arming preconditions, setpoint shaping, dead-man, measurement limits, latched stop,
link loss, the device ceiling, and (with `TB_HOST_SIM`) the same rules against the real firmware code built for the PC.

## What is not covered

- The MAVLink throttle mode is experimental and has not been run on hardware (docs/pending/mavlink-driver.md).
- Nothing here has been run on the physical bench yet. First runs must be done **without a propeller**.

## Physical measures

- **Battery disconnect within reach.** There is none on the bench today. Options: an XT90-S anti-spark loop key on a
  lanyard (pull to cut), or a high-current inline switch. Check the rating against your pack: with 6S and 40 A
  continuous, choose at least 60 A. Add a fuse close to the battery.
- **Cage** around the propeller plane (docs/pending/cage.md).
- Clamp or weigh the bench down, stand out of the propeller plane, wear eye protection.
- First power-up of any new motor, ESC or firmware: no propeller.
